# Product review, November 2026

This review looked at the plugin from five angles, each covered by its own read-only reviewer: UX and UI, marketplace compliance, performance at 1k–50k rows, data safety and edge cases, and product and docs. This document combines what they found and records what the polishing round changes.

## Data safety (must)

| # | Finding | Change |
| --- | --- | --- |
| S1 | Re-import could update or overwrite an **unrelated note**: one at the same path with a different key, or one in the target folder that happens to have the same key value. | Only notes this CSV created are updated: they have a snapshot entry or a source link to this CSV. Any other note is skipped with the reason "not created by this import". An opt-in **Update existing notes not created by this import** option turns this off. |
| S2 | A CSV column named `source` was overwritten by the source link. | When that happens, the link uses `source_csv` instead and the settings dialog shows a hint. |
| S3 | Without a key column, matching goes by row number, so inserting or re-sorting rows updates the wrong notes. | The plugin suggests a unique column as the key, and the preview warns when there is no key. |
| S4 | File names: the length limit was counted in characters instead of bytes, Windows reserved names (CON, NUL…) got through, NFC/NFD forms weren't unified, and case-insensitive collisions were reported as "create". | File names are truncated to 240 UTF-8 bytes, normalized to NFC, and reserved names get an `_` prefix. Path lookups ignore case. |
| S5 | Type inference traps: `+49…` and `1e5` became numbers, a column containing only `no` became a checkbox, Excel serial 60 produced `1900-02-29`, and numbers below 1e-100 became 0. | Detection is stricter in each of these cases, so these values stay text. |
| S6 | An unterminated quote silently swallowed the rest of the file, and blank rows became empty notes. | Parser warnings are shown in the table view and the preview, and rows where every cell is blank are skipped. |
| S7 | Undo also overwrote edits made after the import, and an import that crashed midway could not be undone. | Undo skips notes changed since the import and lists them. Undo state is saved during the run, not only at the end. |
| S8 | A static target folder containing `..` was not rejected. | The folder is rejected with a clear error. |

## Performance (should)

Measured at 50k rows × 20 columns:

- Dry run took 2.3 s in Node, about 8 s expected in Obsidian. The cause was mostly timer overhead.
- Undo and snapshot state came to about 65 MB per CSV.
- The view re-parsed the whole CSV on every render.

| # | Change |
| --- | --- |
| P1 | Yield to the UI on a time budget (about 12 ms) instead of every 25 rows, and throttle progress updates. |
| P2 | Load import state lazily per CSV and store undo data in its own file. Cap the undo data and warn when the cap is exceeded. |
| P3 | Cache the parsed CSV in the view. Keep the duplicate-name counters in a map (fixes 10k duplicates taking 5 s), and precompile templates once. |
| P4 | "Show more" appends rows instead of re-rendering the table. |

Column type inference still reads **all** rows. Sampling was rejected because a single unusual value late in the file would otherwise produce mixed types within a column.

## UX and copy (should)

- Reorder the settings dialog to **Columns → Output (folder, file name, existing notes, key) → Preview → Advanced** (collapsed).
- Use a single scroll area, a phone layout, card-style column rows on narrow screens, and larger touch targets.
- Before the first import, show where the notes will go. The button reads "Import N rows as notes".
- Overwrite asks for confirmation.
- Use the same terms everywhere: outcome labels (New / Updated / Unchanged / Skipped / Failed), "Stop import", and Close as the primary button after a run.
- Type badges get readable labels, a larger click area, and keep keyboard focus after a change.
- Long cell text shows in full on hover. Fix the sticky header offset and add a hint to the sort control.
- Empty and error states say what to do next. Invalid number precision shows a message.
- After an import, offer **Open base** and **Reveal folder**.

## Product (should)

- **Create a base** is on by default when the Obsidian version supports Bases.
- New command: **Re-import all configured CSV files**.
- README: lead with the value proposition, add a quick start, a timesheet + Bases walkthrough, Privacy and data, Limitations, Troubleshooting and a comparison table. Developer and release docs move to CONTRIBUTING.md.
- Sharper manifest description.

## Compliance (must before submission)

- Use `vault.process` instead of `vault.modify`.
- Log only real errors.
- Disclose network use (none), data stored, and files written outside the notes.
- Remove the screenshot placeholder.
- The undocumented `metadataTypeManager` is still used, guarded and switchable. A reviewer may question it.

## Deferred

- Stub notes for linked values.
- Filtering rows before import.
- Importing only rows selected in the table.
- Automatic re-import when the CSV changes.
- German UI.
- Summaries in the generated base.
- Exporting back to CSV.
