# Product review, November 2026

This review looked at the plugin from five angles, each covered by its own read-only reviewer: UX and UI, marketplace compliance, performance at 1k–50k rows, data safety and edge cases, and product and docs. This document combines what they found and records what changed.

Status was checked against the code on 2026-11-24. **Done** means it is in the code; the release is named where it shipped. **Open** items are collected in the [backlog](#open-backlog) at the end. Most findings shipped in 0.1.0; the UX section was later reworked by the two UI passes, so the current layout is in [UI-SPEC.md](UI-SPEC.md), not here.

## Data safety (must)

| # | Finding | Change | Status |
| --- | --- | --- | --- |
| S1 | Re-import could update or overwrite an **unrelated note**: one at the same path with a different key, or one in the target folder that happens to have the same key value. | Only notes this CSV created are updated: they have a snapshot entry or a source link to this CSV. Any other note is skipped with the reason "not created by this import". An opt-in **Update notes not created by this import** option turns this off. | Done (0.1.0; `import/ownership.ts`) |
| S2 | A CSV column named `source` was overwritten by the source link. | When that happens, the link uses `source_csv` instead and the import settings show a hint. | Done (0.1.0) |
| S3 | Without a key column, matching goes by row number, so inserting or re-sorting rows updates the wrong notes. | The plugin suggests a unique column as the key, and the preview warns when there is no key. Without a key, notes are matched by file name. | Done (0.1.0; suggestion reworked later) |
| S4 | File names: the length limit was counted in characters instead of bytes, Windows reserved names (CON, NUL…) got through, NFC/NFD forms weren't unified, and case-insensitive collisions were reported as "create". | File names are truncated to 240 UTF-8 bytes, normalized to NFC, and reserved names get an `_` prefix. Path lookups ignore case. | Done (0.1.0; `import/folders.ts`, `import/pathIndex.ts`) |
| S5 | Type inference traps: `+49…` and `1e5` became numbers, a column containing only `no` became a checkbox, Excel serial 60 produced `1900-02-29`, and numbers below 1e-100 became 0. | Detection is stricter in each of these cases, so these values stay text. | Done (0.1.0) |
| S6 | An unterminated quote silently swallowed the rest of the file, and blank rows became empty notes. | Parser warnings are shown in the table view and the preview, and rows where every cell is blank are skipped. | Done (0.1.0) |
| S7 | Undo also overwrote edits made after the import, and an import that crashed midway could not be undone. | Undo skips notes changed since the import and lists them. Undo state is saved during the run, not only at the end. | Done (0.1.0; `import/undo.ts`, `import/checkpointer.ts`) |
| S8 | A static target folder containing `..` was not rejected. | The folder is rejected with a clear error. | Done (0.1.0) |

## Performance (should)

Measured at 50k rows × 20 columns:

- Dry run took 2.3 s in Node, about 8 s expected in Obsidian. The cause was mostly timer overhead.
- Undo and snapshot state came to about 65 MB per CSV.
- The view re-parsed the whole CSV on every render.

| # | Change | Status |
| --- | --- | --- |
| P1 | Yield to the UI on a time budget (about 12 ms) instead of every 25 rows, and throttle progress updates. | Done (0.1.0) |
| P2 | Load import state lazily per CSV and store undo data in its own file. Cap the undo data and warn when the cap is exceeded. | Done (0.1.0; `<hash>.undo.json`, 20 M character cap) |
| P3 | Cache the parsed CSV in the view. Keep the duplicate-name counters in a map (fixes 10k duplicates taking 5 s), and precompile templates once. | Done (0.1.0) |
| P4 | "Show more" appends rows instead of re-rendering the table. | Done (0.1.0) |

Column type inference still reads **all** rows. Sampling was rejected because a single unusual value late in the file would otherwise produce mixed types within a column. The README lists this under Limitations.
